# SmartFit 美学升级 v2：全局审核与规划（2026-10-19）

> 分支 `feat/aesthetic-v2`，基于 `main` `6d4eb30`（PR #2 合并 + 本机修复「聊天输入区整块可点开键盘」）。
> 起因：开哥反馈“比以前好一点，但还是不够精致”，要求对照 HipLab 最新版（`2d47520`，含 `76ff846` 及之后）在按钮、动效、倒计时上的定制化处理，**吸收方法而不是照搬**；对 App 全部功能做一次审核摸排，以“极简、少即是多、打开只有一段对话、功能从对话里自然展开”为方向做全局规划；深色完成后再做一个同样有质感的对称浅色模式。
>
> 本文是实施的依据。上一版设计语言见 [design-language.md](design-language.md)（v1，本次在其上演进，不推翻：一个强调色 jade、色调分层、按钮金字塔、自绘图标、内置 Noto Sans SC）。

---

## 0. 方法

1. **读 HipLab 最新版**：`lib/hip/ui/hip_widgets.dart`（`HipCountdownRing` / `HipRingPainter` / `HipPressable` / `_HipFlatFace` / 主次按钮 / `HipMediaFrame` / `HipMediaVariants`）、`hip_player_page.dart`（播放器布局、固定高度槽、`AnimatedSwitcher` 节奏、33 ms 计时只重绘圆环）、`hip_tactile.dart` + `docs/tactile-design-rationale-2026-10-19.md`（轻拟物 R1–R6 预算）、`hip_theme.dart`（`HipMotion` 全部时长与曲线）、`hip_routes.dart`（横推 / 被覆盖页 / 容器展开）、`hip_app.dart` 英雄卡的明暗舞台处理、`assets/hip/action-media.json`（46 个动作的浅色渲染）。
2. **摸排我们的 App**：逐页、逐流程、逐状态（空 / 加载 / 错误 / 完成）走一遍代码和截图。为此新增 `test_screens/aesthetic_shots_test.dart`：同一脚本对改前、改后的 App 各拍一组关键屏（对话首页、计划卡、跟练倒计时、动作库、设置 × 深 / 浅），作为对比图来源。
3. **结论落到可检验的清单**：问题按 P1（破坏质感、每次都看见）/ P2（明显但局部）/ P3（细节）分级；每条动效写明时长、曲线、减少动态效果下的降级、是否带触感。

> 顺带发现：沙盒里 `flutter test` 以前“宿主崩溃”的原因是测试监听器的本地 WebSocket 被 HTTP 代理拦截（404）。去掉代理环境变量后全套 102 项测试 47 秒跑完。本轮所有阶段都在沙盒里跑全量测试。

## 1. 从 HipLab 吸收的方法（不是外观）

| # | HipLab 的做法 | 背后的方法 | SmartFit 怎么用 |
|---|---|---|---|
| H1 | `HipPressable`：按下 0.97 缩放 + 平面填充压暗，100 ms 按下 / 180 ms 松开，`easeOut` / `easeOutCubic`，**不用墨水波纹**（容器展开要对按钮截首帧，波纹会让首帧重绘） | 按压反馈是**时序**，不是材质；所有按钮共用一套时序 | 已有 `SfPressable`，补：①触感分级（选择 / 轻 / 中）；②聚焦与禁用态统一；③把仍在用 `InkWell` / `IconButton` / `ChoiceChip` / `FilledButton` 的页面全部换到同一套按压上 |
| H2 | 轻拟物**预算**：全 App 只有分段滑块（会动的实体）和首页「开始」圆盘（视觉丰富背景上的唯一英雄动作）是凸起的，其余靠颜色和层级 | “能被推动的东西才有厚度；只有一个按钮值得浮起来” | 计划卡封面上的「开始」是我们唯一的英雄动作 → 用同一套“顶光 + 发丝边 + 紧贴接触影”的强调拟物（无光晕）；外观分段控件的滑块用中性拟物并**真的滑动**；其他一律平面 |
| H3 | `HipCountdownRing`：发丝轨道 + 渐变弧（尾 38% → 头 100%）+ 圆尾帽 + 头部小亮点；0% 什么都不画；数字换值 `fade + scale .92→1`；进度用 `ValueListenable` 只重绘圆环，页面不跟着重建 | 倒计时是**一个会呼吸的仪表**，而不是进度条；重绘范围最小化 | 新 `SfCountdownRing`：同样的弧与亮点；数字**滚动**（旧数上移淡出、新数自下而上）；**最后 3 秒**圆环与数字做一次呼吸（1.0→1.06→1.0）、数字变强调色、每秒一下选择触感；训练开始一下中等触感；进度 50 ms 刷新，只重绘环 |
| H4 | 播放器：媒体 → 动作名 → 一句字幕胶囊 → 「暂停 · 计时环 · 跳过」→ 固定高度的「下一个」槽（有无下一个都不跳） | **固定槽位**，阶段切换只换内容不换布局；名称、字幕用 `AnimatedSwitcher` | 我们的跟练页信息区高度随阶段变化（标签有无、字幕行数、「下一个」条出没）→ 改为固定槽；名称 / 阶段标签 / 字幕淡入换值；媒体在动作之间交叉淡入 420 ms |
| H5 | `HipMotion`：fast 180 / medium 280 / slow 420；页面 400 / 340；容器 500 / 420；进入 `Cubic(0.2,0,0,1)`，离开 `fastOutSlowIn`；“M3 emphasized 三点曲线不用于页面”；一次转场一个主运动 | **一套动效词汇**，时长按运动距离分级 | 补齐 `SfMotion.page / pageReverse / stagger / roll / breath / exit`；所有普通页面换成横推（被覆盖页左移 25% 并略暗），不再用 Android 默认缩放转场 |
| H6 | 明暗两套**媒体**：46 个动作有 `#EFEFEF` 浅色舞台渲染（带柔和落地影），`stageFor()` 让卡片取视频烘焙底色，浅色英雄卡标题用深字 | 媒体框颜色 = 视频底色，否则就是“贴上去的黑块” | 浅色主题所有封面、缩略图、视频都换浅色渲染（见 §6），舞台色随主题；封面上的标题颜色跟着舞台走 |
| H7 | 字体节奏：页面标题 w800、动作名 26/w800、倒计时数字 `size*.34` 字距 `-size*.012` 等宽数字、说明文字 muted | 层级靠**字重 + 字号 + 颜色**三档，数字永远等宽 | 标题统一 w700→w800 的两档；所有跳动的数字等宽 + 负字距；元信息统一 13/muted |
| H8 | 回归测试把“预算”写成断言（同屏强调拟物 ≤ 1、主按钮无阴影等） | 审美规则可检验 | 新增 `test/aesthetic_budget_test.dart`：对话首页强调色主动作 ≤ 1、拟物只在「开始」与分段滑块、减少动态效果下无缩放 |

**不照搬的部分**：HipLab 是“首页英雄卡 + 底部三个 Tab”的工具型结构，我们是“一段对话”；它的雷达图、自测、套路编辑器我们没有；它把字幕做成描边胶囊，我们的字幕更长（教练语音逐句），保持为无容器的一行 muted 文本 + 字幕图标。

## 2. 全量摸排：逐页 × 状态

级别：**P1** 破坏质感且每次都看见；**P2** 明显但局部；**P3** 细节。

### 2.1 对话首页（`chat_home_page.dart` / `chat_widgets.dart`）

| 状态 | 现状问题 | 级别 | 改法 |
|---|---|---|---|
| 打开（回访） | 第一眼是一个小气泡“说说今天想怎么练？”贴在底部，上方 80% 是空的天空；没有“这是一个助手”的仪式感 | P1 | 问候改为**无气泡的大字**：时段问候（早上好 / 中午好 / 下午好 / 晚上好 / 夜深了）28/w700 + 一行 muted 引导，漂在天空里；它仍是一条对话消息（可被后续消息推上去），只是排版不同 |
| 打开（首次） | 安全对话是正确的，但“我已了解 / 否 / 是”选项与普通 chip 同样式，问题序号不明显 | P3 | 问题气泡加 `1/4` caption；选项保持 |
| 建议 chip | 4 个都是“排计划”的句子，用户发现不了动作库、记录、外观、我的计划这些功能 | P1 | **发现型 chip**：状态驱动的 4–5 个建议，混入「看看动作库」「上次练了什么」「我的计划」「换浅色」「你能做什么」，带 16pt 图标区分“排计划”与“打开功能”；chip 换批时依次入场（40 ms 错开） |
| 输入中 | 发送键有字时变绿，无过渡细节；键盘弹起时消息列表跳一下 | P3 | 发送键箭头缩放切换 180 ms；列表保持 `reverse`（已有） |
| 等待回复 | 三点打字气泡 OK | — | 保持；减少动态效果下静止（已有） |
| 收到回复 | 每条消息同一种 360 ms 上浮；文字 + 卡片同时出现，节奏扁平 | P2 | 助手消息从左下锚点 `fade + 10px 上浮 + 0.98→1` ；用户消息从右下；一次回复的多条消息依次错开 120 ms（先话后卡） |
| 计划卡 | 见 2.2 | | |
| 保存后 | Toast 浮在输入框上方，深色下是 surfaceHigh 块、浅色是黑块，和整体语言脱节 | P2 | 统一 `SfToast`：surface 胶囊 + 勾图标，浅色加发丝边，进出 280 ms |
| 没排出来 / 听不懂 | 文本气泡 + chip，OK；但“这个我帮不上忙”语气偏冷，且不告诉用户能做什么 | P2 | 改为“我只会帮你安排训练”+ 发现型 chip |
| 安全阻断 | 选项「浏览动作库」「重新确认」OK | — | 保持 |
| 左下书签 | 唯一常驻入口，OK；抽屉里还有 3 个入口（动作库 / 自定义 / 关于与设置） | P2 | 见 §4：抽屉只放“我的计划”+ 底部两行（动作库、设置）；自定义计划改为对话展开 |

## 6. 浅色模式方案

### 6.1 结论：对称，素材 93/93 都有浅色版本

| 来源 | 数量 | 浅色做法 | 结果 |
|---|---|---|---|
| Pose-Hub v0.2.0（经 HipLab） | 46 | 取 HipLab `assets/drill_media/light/hip-<id>.mp4/.jpg`（只读复制，HipLab 用 Pose-Hub alpha 帧在 `#EFEFEF` 上重新合成，带 σ12 / dy10 / 14% 的柔和落地影）→ 按深色版同样参数缩到 720²（H.264 CRF 27）、封面 540² | 与 HipLab 浅色完全一致 |
| Drive 绿幕母版 | 47 | 从 `work/drive/green/*.mp4`（1080² #00FF00）**重新抠像**到同一个 `#EFEFEF` 舞台，用抠像 alpha 生成同款落地影（模糊 σ8、下移 7px、14%，按 720 缩放折算），边缘去溢色 | 与上一行同一观感；边缘放大检查无绿边 |

工具：`tools/media/build_light_media.py`（标准库 + ffmpeg，一次一个、`-threads 2`）。输出 `assets/packs/<id>/demo-light.mp4` + `cover-light.jpg`，`pack.json` 的 `media.light = {video, cover, stage}`，`build_packs.py` 重新封装（文件清单与 sha256 包含浅色文件）。`drill-pack-spec.md` 增补 `media.light` 为可选字段（其他 App 不认识也能用）。体积：约 +11 MB（每个浅色视频 100–170 KB）。

**为什么不选“浅色主题里保持深色画框”**：那是上一版的折中，开哥看过“比以前好一点但不够精致”，浅色页面中间一块黑框正是不精致的来源之一；HipLab 已经证明重新合成可行，我们有全部母版和 alpha 来源，成本可控（约 11 分钟沙盒算力）。

### 6.3 跟随系统 + 手动

- 设置里「深空 / 浅色 / 跟随系统」三段（已有），滑块真滑动。
- 对话里说「换浅色」「深色模式」「跟随系统」直接切换，回一句确认。
- **默认改为「跟随系统」**：上一版默认深色的唯一硬理由是“没有浅色媒体”，现在已经补齐；已经手动选过的用户不受影响（存储里保留原值）。
- 切换时整树在同一帧重建（`SfPaletteScope`，已有），不丢页面状态；视频控件按主题重新加载对应版本。

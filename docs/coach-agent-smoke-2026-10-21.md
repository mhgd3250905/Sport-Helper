# CoachAgent 0.3 首次真实 Worker 验证（2026-10-21）

本轮验证 SmartFit 的 Skill Agent 多步调用、本机用户记忆及关闭记忆后的隔离。Base URL 为 `https://api.uuugk.win/v1`，模型为 `deepseek-v4-flash-0731`；App Key 仅经 dart-define 注入，设备 UUID 首次生成后保存在本机并复用，不发送 Authorization。SDK 默认 `maxSteps=10`，HTTP 单次 120 秒且不自动重试，App 整轮保护超时 1,230 秒，随时可取消。

## 方法与判定

显式执行 `tools/coach/run_agent_smoke.ps1 -AppKeyFile '<本机文件>'`，运行 `worker_agent_smoke.dart`。这是实际 App 的 `AiCoachConfig` → `AiChatEngine` → `ChatController` → SDK `CoachAgent` 链路，使用 App 实际 93 动作目录和 SDK smartfit profile。测试在 Flutter 测试宿主中向真实 Worker 发请求，本机文件适配 `LocalStateStorage`；不是假模型，也不是本轮真机 UI 验收。

每轮记录 `CoachTurnResult.steps/reads/records/usage`、状态、耗时、回落原因与最终 typed 卡片。token 合计为 `promptTokens + completionTokens`，reasoning 已包含在 completion 中，不重复相加；失败响应没有返回用量时只能记录 SDK 获得的用量，不能推断服务端未消耗 token。`CallOutcome` 诊断映射显式覆盖 `toolStep`。

前三个问题各用独立新对话、记忆关闭，避免前一案例污染。记忆案例先开启并发送「我是新手，家里有哑铃」，检查实际本机条目；再开新对话询问未注明器械的计划，核对请求记忆摘要与最终回复。关闭记忆后保留本机记忆表，再开新对话重复同一计划问题，核对没有记忆摘要、remember/forget 工具或旧聊天/Slots 的影响。关闭开关不会删除当前聊天，显式新对话是隔离验证所需。

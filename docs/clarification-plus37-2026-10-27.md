# +37 训练参数追问

## 原因和接入

原 App 将 `coachContext`、`pending` 或上一张计划中的场景、器械、时长传给 SDK；这些值可能只是出方案时采用的默认值，SDK 因而认为用户已经提供了条件。新训练请求不再把这些聚合值作为已知条件。SDK 活会话从当前会话原始用户消息和表单回答判断场景、器械、时长；明确调整当前计划时仍可沿用该计划。安全保护条件继续保留。

重启后的展示历史并未恢复进 SDK Agent。App 只从展示历史保守恢复可辨认的场景与时长；复杂或含糊的历史器械条件可能需要重新回答，避免旧值覆盖新的选择。

表单使用 `ugk_coach_ui` 的澄清组件；选择后经 App controller 调用 SDK `answerForm`，直接出方案经 `skipQuestion`。这两条接线原本已有，本次以交互回归覆盖。

## AI 记忆

SDK 的长期记忆中 scene 和 equipment 会作为模型的参考资料进入提示词；它们没有直接填入 SDK 参数推断的结构化已知字段。本次没有修改记忆读写或提示逻辑。模型仍能看到记忆内容，不能把这理解为记忆完全不影响生成。

## SDK 已知限制

独立探针在完全不传 App 上下文、关闭长期记忆的条件下复现：同一会话首次跳过追问后，SDK 将默认值写入已装饰的历史用户消息；下一次新训练请求可能把它们重新识别为已知，从而拒绝应有的追问。这是 `ugk_coach-v0.7.0` 的 SDK 行为，本次未修改 SDK，也不以 App 历史伪造或清空掩盖。新对话四个验收场景和此同会话问题需分别判断。

## 验证边界

自动化覆盖真实 App controller、SDK 追问门禁、UI 表单选择及跳过；固定响应测试不等同于真实服务或真机测试。实际服务结果、APK 构建和设备验收以交付回报为准。

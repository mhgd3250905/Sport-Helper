# SmartFit 固定玻璃拆分实验（+19）

后续九格真机已完成，选用“仅计划卡会话建议条静态”作为 +20 默认，见 [真机拆分结论与最终默认](performance-fixed-glass-phone-review-2026-10-23.md)。下文保留 +19 发包时的实验说明与待采样状态。

本包用于采集固定玻璃各元素及材质的同场景对照，不预先决定最终默认。+18 的计划卡默认 P99 9.215ms、超预算 3.951% 尚未达标；同场景关闭全局玻璃后 P99 4.607ms，剩余优先项为保留的固定玻璃与滚动内容合成。来源见 [+18 真机复测](performance-static-scroll-cards-phone-review-2026-10-23.md)。星尘、SDK 与锁文件保持原样，当前分支 `feat/performance-baseline`，不合入 main 或推送。

## 场景与真实元素

产生上述数据的计划卡场景使用正式 `ChatHomePage` 承载 72 条消息和 12 张计划卡，不是 `PlanPage` 详情。固定玻璃实际只有输入框和建议条内的胶囊。该承载页没有独立玻璃顶栏/底栏；`PlanPage` 的顶栏与底部开始按钮原本也是静态，因此两项临时开关显示 N/A 并禁用，不制造无变化的假格。

新增 `SfFixedGlassSurface`，为每个固定控件包独立 `RepaintBoundary` 和仅覆盖自身形状的 `ClipPath`。浅深主题、原控件尺寸、子控件交互保留。实验策略只对内测计划场景 scope 生效，普通聊天继续使用原真玻璃材质；滚动卡片仍静态、默认无捕获源。

去饱和度实际将材质 saturation 设为 1：minimal 的背景过滤由两个减为一个，原 blur 保留。半模糊实际为浅色 1.5→0.75、深色 1.2→0.6。两者可组合。关闭单一元素时保留控件、内容、尺寸和交互，将该元素背景替换为静态仿玻璃。

## 手机采集流程

1. 覆盖安装 +19 arm64 internal release（versionCode 2019），保留 +18 包和报告。保持同手机、浅色、120Hz、竖屏、原字号/显示缩放及星尘偏好。实验不切换星尘。
2. 聊天输入框左侧书签 → 设置 → 导出性能报告 →「固定玻璃拆分 · 计划卡与聊天采样」。这是新入口，原八格仍单独保留。
3. 点本页「开始新一轮」，依次跑下面九格。每格点「采样此配置 · 32 秒」，自动往返滚动，结束返回后再点下一格；约 5 分钟加预热/操作时间。无需手动调整六个临时开关，预设会应用对应配置。临时开关供额外手动格使用，不覆盖标准格。
4. 整轮冻结同一玻璃上限，每格固定 72 条消息、相同动作/封面/顺序、800 逻辑像素/秒、3,200 像素区间，每 4 秒折返。前两秒与稳态仍按原 32 秒协议分开。采样中切后台、变尺寸或混条件无效，只重跑对应格。
5. 九格完成后点「导出固定玻璃实验 JSON」，通过系统分享保存回电脑，将 JSON 路径发回。报告应为 `raster_controls_v4`，新格位于 `fixedGlassCases`，原八格位于 `cases`。

## 首次进入与真实预热

「进入前显式预热」在原实验页上完成，目标路由尚未创建。真实 PlanCard、输入框与建议条正常 layout/paint，等待实际本地封面/静态 cutout 解码及胶囊入场，再调用 `RenderRepaintBoundary.toImage` 完成一次离屏栅格化；准备提示遮住该绘制，不使用 Offstage、透明度 0 或移出屏幕来假装预热。无 SDK、视频、网络请求、图片编码或文件写入。

准备树逻辑尺寸不超过 480×480、输出不超过 200 万像素，尽量使用真实设备 DPR，报告记录实际尺寸/DPR/耗时。解码和栅格化各有 3 秒超时；图片、Overlay、生命周期监听均释放，超时后返回的 image 也释放。中断、错误、尺寸不支持如实记为 failed/unsupported；预热格只有 succeeded 才能作为有效预热对照。成功代表完成一次绘制，不声称有 Timeline 着色器编译事件。

每格的 `entryFirst2Seconds` 在 push 目标页前申请，统计真正进入该路由的前两秒，包含开始滚动前的转场；不拿滚动起点的前两秒替代。记录预热实际状态、进入序号、此前是否访问过目标页、条件混合与生命周期异常。预热自身发生在前页，不计入目标页稳态。

九格中后采的预热格已受前面页面访问影响，不能由此认定首次进入改善。专门比较首次进入时：重启 App 后首先采 baseline 并导出；再次重启 App 后首先采 baseline_prewarmed 并另行导出。报告重置不清除进程内访问历史。首页可能已绘制共享计划/玻璃组件，重启也不保证 GPU/驱动完全冷，因此只描述目标页面首入观测，不单独归因着色器编译。原 17.777ms 尖峰的复测结果继续单列，不阻断稳态方案选择。

## 数据与默认方案选择

逐帧记录实际页面、角色存在性、各角色是否真玻璃、基础/有效 blur/saturation、星尘、质量、renderer、刷新率、主题/窗口/缩放及预热状态和绘制尺寸；有界内存累计，不逐帧写文件。每格独立，混条件和缺失数据不能补 0。脚本生成同场景平均/P99/超预算表与进入旁表：

```powershell
python tools/performance/fixed_glass_matrix.py 'F:/test-logs/SmartFit-performance-NEW.json' -o 'F:/test-logs/SmartFit-fixed-glass-table.md'
```

最终默认配置待真机结果确认，目标为计划卡稳态 Raster P99 <8.33ms、超预算接近 0。按开哥规则选择：单一元素为主则仅该元素静态；去饱和度或半模糊足够则选更贴近原观感者；均不够则计划滚动场景固定栏全静态、聊天保留真玻璃。当前实验包默认仍是 baseline 材质，未把候选或测试合成数据冒充最终方案。生产不带实验入口、临时开关、预热实验或帧记录器。

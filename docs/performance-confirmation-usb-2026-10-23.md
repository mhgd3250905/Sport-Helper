# +20 USB 真机四格确认：浅色聊天未达标，不合入

四格原始 JSON 已取回，期待的 4/4 格及其独立进入窗口均通过现有分析器校验。浅色计划卡、深色计划卡、深色聊天的稳态 Raster P99 低于 8.33ms；**浅色聊天 P99 为 11.263ms，3057/3255 帧超预算（93.917%）**，因此 [四格合入门槛](performance-confirmation-gate-2026-10-23.md) 未通过。按开哥要求仅报告数据，不继续修改运行时代码，不合 main、不推送、不 rebase 图标/品牌色分支。

设备为 Xiaomi 2602BRT18C，Android 16/API36，非模拟器。两份报告的非主题 metadata 完全一致：Impeller/Vulkan 已验证、120.00000762939453Hz，逐帧预算 8.333332803514303ms。视口 393.846153846 × 852.923076923，DPR 3.25，字体比例 1。

两主题均采用实际 `premium / comparison_locked`、全局玻璃开、列表卡片静态、星尘开、预热关闭。计划卡仅建议条静态，输入框真玻璃；普通聊天输入框与建议条均真玻璃。实际浅色真玻璃 blur 1.5 / saturation 1.1，深色为 1.2 / 1.15；静态建议条为 blur 0 / saturation 1。承载页没有独立顶栏或底栏玻璃，两角色为 N/A，不能据此归因。

浅色先采计划卡再采聊天并导出。原始文件保存到电脑后切深色，在拆分页“开始新一轮（清空全部性能统计）”，再采同样两格并导出。四格均为安装包中的“当前默认”入口，使用 72 条固定测试会话及约 32 秒自动滑动脚本；每次点击后静置 37 秒，采样期间没有截图、UI dump、手动滑动或切后台。每格条件唯一，无溢出、未归因帧或帧时序异常。没有为追求通过重跑择优。

## 数据支持范围

这轮只能确认：所测 +20 默认方案的浅色长聊天稳态不达标，计划卡两主题及深色聊天达标。没有同主题、同聊天场景的滤镜开关对照，不能从计划卡与聊天的差异归因某个固定玻璃元素；浅/深色还同时改变配色和材质基础参数，且采样顺序固定、每格仅一次，也不能据此拆出模糊、饱和度或其他某一层的责任。不把既往 +19 不同档位数据当成本轮修前对照。

本轮没有 DevTools Timeline 的着色器事件证据，不能将进入尖峰断言为着色器编译，也不能用浅色首次进入与深色再次进入宣称预热收益。预热始终关闭。

P90/P99 是原记录器直方图上界估计（误差不超过耗时的 6.25% 或 1μs）；平均与最差为精确聚合值。超预算按 UI/Raster 各自耗时与设备逐帧预算比较，**不等于屏幕实测丢帧率**。这轮使用内测 release 包的 Flutter FrameTiming，并非新增 DevTools Timeline 实测。

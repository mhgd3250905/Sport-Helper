# +21：所有聊天建议条静态仿玻璃

本轮授权将建议条静态仿玻璃扩展到所有聊天会话，输入框仍保留原真玻璃。星尘、SDK、预热（关闭）、列表结构和其他渲染参数不改。含计划卡会话原本就使用此策略，所以本轮不重跑已达标的计划卡两格。

## 改动与采样标识

`ChatHomePage` 对所有内容采用同一建议条策略；`isPlanContext` 仍按实际计划卡内容记录，不再作为普通聊天恢复真玻璃的条件。建议条沿用已实现的静态底色、细描边与轻阴影；输入框默认 blur、饱和度和质量策略保持原值。

内测当前默认聊天格改记 `chat_suggestions_static__longChatScroll`，直接运行真实页面，不用实验 scope 覆盖其默认。历史 `chat_baseline__longChatScroll` 保留显式全真玻璃策略用于兼容旧报告，不将新默认误标成旧基线。

仅为用户授权的条件补采增加 `chat_suggestions_static_input_blur_1_2__longChatScroll`：浅色输入框绝对 blur 为 1.2，建议条仍静态，其他材质和参数不变。该值只在内测输入框生效，正式默认不变，采样退出后恢复。深色按钮禁用，记录器和分析器也拒绝将深色该格判为有效。生产版不含内测入口或记录器。

每帧条件、实际角色材质及进入窗口继续记录；新配置使用独立有界槽位，不写逐帧文件。旧九格实验及原始报告仍可读取。

## 本轮确认步骤与合入条件

使用 +21 ARM64 internal release 包、同一 USB 真机及原 72 条聊天脚本。保持星尘开启、相同字体/方向/刷新率、全局玻璃开、列表卡片静态、预热关闭，玻璃在采样页按原方案锁档。

1. 浅色运行“复测当前默认 · 聊天 · 32 秒”，期间不截屏、dump UI、手动滑动或切后台。
2. 导出并保存浅色原始 JSON，核验默认格身份与有效性。
3. 若浅色默认仍未达标，追加一次“补采浅色聊天 · 输入框模糊 1.2”，保留默认格与补采格分别统计并导出；不把补采成绩冒充默认成绩，不继续优化代码。
4. 浅色文件保存后清空本轮统计，切深色运行同一当前默认聊天格，单独导出。相同配置只保留一个槽位，不能两主题都采完只导出一次。

稳态分别报告 UI/Raster 平均、P90、P99、最差帧、超预算数量与比例。进入目标页前 2 秒与脚本前 2 秒分开统计，不作为本轮稳态合入门槛，也不据尖峰断言着色器编译。

本轮门槛为浅色、深色**当前默认聊天**两格 Raster P99 均 <8.33ms、超预算接近 0。保留用户原文“接近 0”，不擅自发明阈值。两格通过后仍须开哥同意，才合入 main 并推送，之后才 rebase 图标/品牌色分支。此处取代 +20 的自动条件合入授权；不能直接套用此前授权执行合入。

若浅色仍未达标，仅追加授权的 1.2 对照格并报告，不继续修改代码。SDK、星尘和预热不在本轮修复范围。

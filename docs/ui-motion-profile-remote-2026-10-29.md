## 一项一份，先帧数据、再录屏

1. 在手机打开该包，进入输入菜单→设置→“导出性能报告”→“性能报告”页。先选好本次浅/深主题并保持原星尘、字号、刷新率和省电状态；记录设备型号、系统版本、实际刷新率和这些条件。
2. 点“开始新一轮（清空本轮统计）”。这个按钮只重置内存FrameTiming，不清聊天/历史。返回目标页，只操作下表同一场景；首帧/页面进入类从操作开始全程保留，不把最慢的前两秒删掉。
3. 返回性能页点“结束当前格”（若存在），再“导出性能报告”，保存原始JSON；不要只截P99页面。App已有尾帧等待与系统分享。每个场景、主题、冷/热缓存分别保存；记录操作步骤、重复次数及大约开始/结束时间。
4. 再做同样步骤录一段展开/切换/收起或该场景的视频，用于识别跳动/闪烁/硬切。优先让纯帧数据轮不录屏，视频另轮采，避免录屏开销混入基线；两轮不能逐帧冒称同一次。若需精确关联慢帧与视频，可另做同时采集轮并明确标注录屏开启，不与纯帧轮合并。
5. 回传原始JSON、对应MP4、公开包回执/文件名及操作说明。VM连接文件保留本机；不需要密钥、私密连接地址或整份系统日志。

当前报告的sdkRef常量仍旧且可能被过滤，正确包身份以公开APK回执的actual source、sourceFingerprint、SDK与哈希为准。JSON的 `metadata.buildMode` 应为profile、`isEmulator` 应为false，实际设备元信息应可用；`sourceFingerprint` 应为 `80ce256285852735fbb0b218c1c62c865b06fa377cee422e0d49d9c3b40166f7`。这些运行字段未验证前不判数据合格。

## 数据窗口与限制

手机导出的rawFrames包含设置和回到页面的转场，不能直接取total最大值就称某个动画峰值。单项文件能避免多场景混杂，仍应记录边界；我的计划/弹层可能共用other_route，完成态仍标training。我们会明确窗口是否可定位，无法独立定位的项保留待测，不填伪精确值。

若你使用连接真机的电脑，可用现有 internal-profile VM 扩展或 DevTools选择精确操作窗口，导出原始性能trace；工作区已有 `tools/performance/profile_capture.dart`。此能力已经存在，本次没有新增采集代码。仅有手机JSON/录像且边界无法定位时，先出该段场景级结果，必要时再补精确trace。

不要用旧“浅深×五场景十格”工具直接当这份全App报告完成，也不要用它的8.33ms/P99或刷新周期超标数替代本次 >16000us。检查rawFramesTruncated=false、原始数量完整、设备/源码/模式一致。UI/Raster分别统计；录屏本身不能证明全部帧≤16ms。

收到资料后，本报告再补每项最大值、UI/Raster与去重超标帧数、视频定位、采样边界及按实测严重程度排序，交开哥与Hark定案。本步不修改任何动效代码。

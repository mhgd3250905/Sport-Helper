## 使用

内测包自动记录。遇到问题后进入「设置 → 运行日志 → 保存日志到手机」，在系统文件窗口选择「下载」或其他目录，保存 `SmartFit-runtime-<UTC时间>.json`，再手动发给开发者。写入和关闭文件成功后才显示保存成功；取消不删除已有记录，失败可以重试。没有自动上传，也不申请全盘存储权限。

日志存在 App 本机独立存储键中，重启可恢复；保留最近 7 天、最多 1500 条和 512 KiB，先达到的限制生效，轮换最旧记录。磁盘保存失败不阻断训练，当前内存中的记录仍可导出。异步持久化是尽力而为，断电、进程被强杀可能丢失尚未落盘的末尾记录；不是系统原生崩溃转储。

正式 release 关闭日志和入口。内测 flavor 根据 Flutter 实际 `FLUTTER_APP_FLAVOR` 开启；仅 debug 可额外用 `SMARTFIT_RUNTIME_LOGS=true` 进行网页测试。正式 flavor 无法用该 debug 开关开启。

## 关键节点

| 范围 | 记录内容 |
| --- | --- |
| 启动 | 版本、平台、着色器/媒体/动作目录/存储就绪，身份持久化失败类型；只记录 App Key/身份是否存在 |
| 聊天 | 每轮关联编号、输入字数、开始/取消/新对话、本地快捷指令或 SDK 路由、准备素材和呈现结果耗时 |
| AI | 每次请求开始/返回/错误、模型、次数、步骤、耗时、错误 HTTP 状态、重试原因、工具名称、token 计数、校验后采用或回退原因 |
| 计划/素材 | 模板生成、后台预取、每个动作/包的阶段、Wi-Fi/离线政策、下载字节采样、校验失败分类、清理缓存的开始/结果 |
| 训练 | 开始、可见动作切换、暂停/继续、每 30 秒心跳、完成/提前结束、实际 active 时长、结果保存成功/失败、页面关闭和重播新轮次 |
| 视频/语音 | 视频表面请求/更新/关闭；语音请求、加载耗时/失败、播放调用返回、中断与停止；数字及提示音每 30 秒汇总 |
| 异常/导出 | Flutter/未处理异常的类型，导出开始/取消/失败/完成，App 前后台状态 |

每条有 UTC 时间、该次启动内序号和运行时长；聊天、训练、请求等使用关联编号。迟到的 AI 响应保留旧轮次编号，本地回复清空旧 AI 诊断结果。模型的文本、推理原文、请求/响应正文、工具参数、记忆内容、密钥、设备 UUID、URL、文件路径、原始异常文本和堆栈均不进入导出；字段及机器标记字符串均经过白名单。

视频表面请求和素材 ready 不能证明视频已解码或实际播放。共享 SDK 没有公开首帧/解码错误观察口，部分音频播放错误会被 SDK 内部吞掉；`voice.playback.settled` 只表示调用结束，不证明扬声器实际发声。训练心跳记录墙钟时间，`training.finished.durationMs` 才来自 SDK 的 active 时间。预取 end 只代表任务返回，素材是否可用要结合各资源最终 phase；builtin ready 不冒充运行时 SHA-256 校验。

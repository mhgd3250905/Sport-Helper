## 已实测问题（未修复）

1. 原文“在家只有哑铃，20 分钟全身”产生计划后被 SDK 准入门禁拒绝，界面实际提示 **“这次未能完成回复，请重试。”**；该段 2 次调用已发生，未冒称模型成功或用旧 reply 代替。
2. 健身房计划在确定性回归中可复现器械声明为空：SDK 选到需要垫子、椅子、弹力带的动作，但计划 `equipment=[]`，原门禁拒绝 7 项。原正向失败与诊断留在 `gym-plan-admission-issue.json`。全量中的负向用例只确认门禁保持拒绝，不代表这个 SDK 产品缺陷已修复；另一个器械明确的居家计划才验证正常显示、编号和保存。
3. 肩痛合成场景按原选项回答“抬手或发力时刺痛、有卡住感”后，模型仍附带 `h-incline-pushup`（扶凳上斜俯卧撑）。这是实际模型输出，文案和未审标签需人工复核；结构范围检查通过不等于安全验收。

“第二个换掉”实际仅将 `h-reverse-crunch` 换为 `h-supine-bilateral-leg-raise`，其余四项 ID 原样保留。补充会话实际用 `answerChoices` 提交两项原选项，随后发送真实快捷按钮“换个场地”的原文。

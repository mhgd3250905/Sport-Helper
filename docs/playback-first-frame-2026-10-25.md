# 训练待播图与视频首帧对齐（待真机确认）

基于修复分支 `1b708e4` 继续，内测版本 `0.1.0+25`。本任务不修改 `release/1.0`，main 仍等待开哥真机确认。

## 原因与修复

原素材工具用 Pose-Hub 各主题的 `_2.webp` 选定关键姿势生成封面，播放器却从视频 0 秒起播；两者不是同一帧，静帧切换到视频时姿态会跳变。SDK 的起播和首帧门禁正常，因此本轮只修改 App。

打包时从经原始清单 SHA 验证的每条实际 MP4 解码第一帧，生成独立 `playbackPoster`。93 个动作各自浅/深两套，共 186 张。`ExerciseVideo` 使用当前主题的该图，视频保持从 0 秒开始；沿用 SDK 的快速切换合并和真实首帧淡入。源视频、Pose-Hub 导出包、原选定封面和缩略图均保持原字节。没有视频的动作继续使用原静帧。

新增索引描述记录来源视频 SHA、帧序号 0 和起播时间 0。静态封面、列表及聊天卡继续读取原 poster，避免影响它们的选定姿势。FFmpeg 仅用于构建素材，App 运行时不增加解码依赖。

## 验证与交付

只做本轮相关验证：Python 素材测试 14 项与已生成清单 1 项通过；Flutter 浅深主题、首帧待播、手动预览和快切交接 9 项通过；改动文件静态检查无问题。两个反馈动作的浅深视频实际解码首帧与新待播图逐像素比较通过，差异仅为 WebP 压缩；原 558 个视频/封面/缩略图描述和文件 SHA 保持不变。
